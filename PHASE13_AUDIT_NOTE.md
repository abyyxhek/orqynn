## 4. Design decisions

| # | Decision | Alternative rejected | Why |
|---:|---|---|---|
| 1 | **An undeclared scope conflicts with everything, including another undeclared scope** | Treat empty as "no constraint" | The alternative makes `Task::new()` — the constructor every task starts from — silently safe to race. That is the exact failure this check exists to prevent. Cost is stated loudly: a caller who declares no scopes gets no concurrency |
| 2 | **Overlap = one normalized path is a prefix of the other** | Semantic / file-level analysis | Lexical is deterministic, cheap, and testable. Semantic analysis is deferred and would need to read files |
| 3 | **Conservative: a directory scope conflicts with everything inside it** | Exact-file matching | A false conflict costs one round; a miss costs a corrupted merge |
| 4 | **`\` normalized to `/`** | Require POSIX separators in declarations | Orqynn is developed on Windows; requiring POSIX would mean the developer's own paths silently miss |
| 5 | **Relative `..` that escapes the root is REJECTED, not clamped** | Clamp to `.` | `../src` names ground outside the project, which Orqynn is not managing. Rejecting is auditable; clamping invents a scope nobody declared |
| 6 | **Absolute `..` clamps at `/`** | Reject | `/..` is `/` by definition in POSIX |
| 7 | **Case-sensitive on all platforms** | Case-insensitive on Windows/macOS | Platform-conditional matching would make the same plan produce different assignments on different machines. Determinism across platforms was judged more valuable than closing the gap; the gap is documented and pinned by a test |
| 8 | **Absolute and relative declarations of the same tree collide** | Treat them as disjoint | They may well be the same files. Conservative, and simple |
| 9 | **Check in `validate_assignment` (pure), not only in `assign_at`** | Check inline in `assign_at` | `validate_assignment` is the documented pure half of the step and is directly unit-testable. It already receives `plan_tasks`, so no signature change was needed |
| 10 | **SCHEDULE checks in-round before proposing any pairing** | Rely on ASSIGN to catch it | The in-round check is first, so a conflict is reported as a conflict instead of surfacing as a refusal the caller must know to interpret |
| 11 | **Two reporting channels kept** | One | `unassigned` = no agent was free this round; `refused` = the store denied a proposed pairing. Both are structured; collapsing them would lose information |
| 12 | **`UnassignedReason` loses `Copy`** | Force `Copy` elsewhere | `ScopeConflict` carries a `TaskId`, which is not `Copy`. `Clone` was added and `unassigned()` clones the reason — allocating only when a real conflict exists |
| 13 | **`TaskSpec::scopes` takes `IntoIterator<Item: Into<String>>`** | One path at a time | Reads well chained (`.scopes(["a"]).scopes(["b"])`) and matches the existing `depends_on` / `expects` builder style |
| 14 | **No migration, no store method, no new crate** | Add a `blockers` table (migration `0004`) | Conflict detection does not require it. The audit plan proposed it; it was scoped out to keep the phase minimal and avoid touching `director-store` at all |

## 5. Limitations

1. **Undeclared scopes serialize concurrency.** Any caller not yet using `.scopes(...)` gets no
   parallelism. Intended and documented; it is the largest behavioural change in this phase.
2. **Case-insensitive filesystems.** `src/Auth` and `src/auth` collide on disk on Windows and
   macOS but not in Orqynn. Pinned by test so it cannot change silently.
3. **Coarse directory scopes cost throughput.** Declaring `src` rather than
   `src/auth/login.rs` refuses work that could have run in parallel.
4. **Cross-project scopes are not compared.** `assign_at` lists tasks for the task's own project.
   Correct while a project is one repository root; would need revisiting if Orqynn orchestrates
   several checkouts of one repository.
5. **A replacement agent's briefing omits its scope.** `ContinuationPackage` has 15 fields and
   none is `scope_paths`, so `RecoveryBuilder` briefs a replacement with its contract, history and
   next action but not what it may touch. Enforcement is unaffected — ASSIGN and SCHEDULE still
   refuse correctly — so this is a completeness gap in the briefing, not a hole. Verified during
   final review.
6. **Live MCP suites unverified** in this task — binaries absent.
7. **`ScopeOverlap::paths` may contain duplicate pairs** when two tasks each declare several
   scopes and more than one pair collides. Cosmetic only: the boolean verdict and the rendered
   `describe()` message both dedupe or ignore the duplication.

### The concurrency gap, stated plainly — and verified against the store

`validate_assignment` operates on a task list read *before* the write. Two concurrent `assign`
calls for two overlapping tasks could both read "nothing in progress", both validate, and both
proceed. **Verified against the actual implementation, not assumed:**

- `assign_at` reads the active plan, the task, `list_tasks(project)`, the agent, and the sitting
  assignment at `assign.rs:122–149` — **all outside any transaction**.
- `assign_and_start` opens its transaction at `assignments.rs:346` with
  `conn.transaction()`, which is rusqlite's `BEGIN DEFERRED`. Inside it, it re-reads only
  `previous_status` (`:354`) and then writes (`:370`). **It never re-checks scope.**
- The two concurrent transactions touch **disjoint rows** (`tasks.id = A` vs `tasks.id = B`,
  different assignment rows). SQLite serializes writers in WAL mode and `busy_timeout=5000ms`
  makes the second wait and then succeed — but there is no shared row and therefore no lock
  contention and no conflict detection.
- `idx_assignments_active_per_task` is `UNIQUE (task_id) WHERE status='active'`. It guarantees one
  active assignment **per task**; it says nothing about scope paths, which cannot be expressed as a
  partial index anyway.

**Conclusion: the race is real.** Re-reading `list_tasks` does **not** prevent it — the read
happens outside the transaction, so the second caller observes the world before the first
assignment commits.

### Minimal follow-up design (not implemented here — no migration introduced in this review)

The check does **not** need a new table. Because SQLite serializes writers, making the check and
the write share one transaction that takes the write lock up front is sufficient:

1. In `assignments::assign_and_start`, replace `conn.transaction()` with
   `conn.transaction_with_behavior(TransactionBehavior::Immediate)`. `IMMEDIATE` issues
   `BEGIN IMMEDIATE`, acquiring the reserved write lock before any read, so the read snapshot is
   taken *after* any competing writer has committed.
2. Inside that transaction, re-read the project's tasks and re-run the same scope check
   `validate_assignment` runs (`Task::scope_overlap` against `InProgress` rows only).
3. Return a store-level error that `assign_at` maps onto the existing
   `AssignError::ScopeConflict`, so no new variant is needed.

This needs **no migration and no schema change**, because the invariant is enforced by the
transaction rather than by a constraint. A `task_scope_locks` table was considered and rejected:
prefix overlap is not expressible in a SQL `UNIQUE` index, so it would require a row per scope
leaf and would still need the same transactional read.

**Tests that would prove it:**

- Two tasks with overlapping scopes, two agents, `tokio::join!` on two `assign` calls — assert
  exactly one `Ok` and exactly one `AssignError::ScopeConflict`. This is the test that fails today.
- The same with **disjoint** scopes — assert both succeed, so the re-check does not over-refuse.
- A regression asserting the transaction behavior is `Immediate`, so the fix cannot be silently
  downgraded to `Deferred` by a future edit.
- The existing `two_concurrent_writers_on_the_same_version_see_one_winner_and_one_conflict`
  (store integration) already covers the same-row write race and should continue to pass.

Until this exists, Phase 13 is complete for the **step-sequential** loop Orqynn is today, and
incomplete for any concurrent caller. That is a documented boundary, not a hidden defect.
